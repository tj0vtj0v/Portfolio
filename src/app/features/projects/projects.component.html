Structure

A lazy-loaded Angular frontend communicates with a Python API backed by PostgreSQL. Separating these services lets each part evolve independently as the tools grow.

Deployment

GitHub Actions builds the frontend and copies it to my Raspberry Pi. Docker Compose runs the API and database as separate containers.

Access & isolation

Workspace routes require authentication. The API authorises access to stored data, while the public portfolio stays accessible without an account. Containers separate service processes.

Formula Student · Camera perception

From pixels
to cone positions.

A driverless car needs more than a detection in an image. It needs to know where that cone is relative to the car.

The camera pipeline retrieves stereo images, transforms them for neural-network inference, and projects the detected bounding boxes into local cone positions. The results from the two cameras are associated and merged before being passed to the rest of the driverless stack.

My work spans development, validation, and deployment. The implementation uses C++, TensorRT, the ZED SDK, and OpenCV; ZeroMQ and Protocol Buffers carry the results between modules. Image preparation and latency are part of the practical work of making this run onboard.

Formula Student · In development

Building a map.
Finding our place in it.

The mapping module turns local observations into a shared picture of the track and the car's position.

I'm developing a Graph SLAM approach in C++. It represents vehicle poses and cone landmarks as a graph, connected by odometry and observation constraints. Optimising that graph helps reconcile the measurements into a consistent map.

The current implementation separates real-time localisation from the SLAM backend, exchanging measurements and estimates between them. It also includes landmark association, loop-closure constraints, and graph output for debugging.

This work is still in development; the diagram explains the approach rather than claiming a validated racing result.

03 · A personal research platform

A VTOL of my own.

Planned · Concept stage

Why build it?

I want to build a drone as a platform for learning and experimentation, bringing together robotics and geoinformatics. Vertical take-off and landing would make it possible to explore fixed-wing flight without needing a runway.

What I want to explore

The plan starts with designing and manufacturing the airframe, then developing the PCBs and integrating sensors such as cameras and LiDAR. A Jetson Orin is a candidate for onboard computing, with autonomous flight experiments and aerial mapping as longer-term goals.
